# 企业管理系统 · 业务操作手册

> 面向使用者与接手开发者的业务逻辑总览。按角色与模块组织，含状态流转与关键规则。
> 系统入口：Web `http://8.155.128.225/`（PC，功能全量）｜移动端 `http://8.155.128.225/m/`（员工高频场景）
> 技术架构见 README.md；部署见 DEPLOY-ALIYUN.md；本文只讲"业务怎么运转"。

## 一、角色与权限

| 角色 | 可见范围 | 典型操作 |
|---|---|---|
| 超级管理员（admin） | 全部菜单 | 系统管理、审批、全部业务 |
| 普通员工（common 角色） | 首页 + 员工工作台 | 打卡、请假、报销、补卡、汇报、聊天、消息 |
| 访客/未登录 | 登录页 | 登录、注册（注册需审批通过后才可登录） |

- 登录需选择租户（生产仅"企业平台"）+ 用户名密码；验证码生产可开启（当前关闭）。
- 单设备互踢：同一账号在 PC / 移动端登录会互相踢下线（后登录者生效）。

## 二、人事考勤（员工自助）

### 2.1 打卡（PC 工作台 / 移动端工作台）
- 每日可打上班卡、下班卡各一次；重复打卡以当日既有记录为准。
- 判定规则：上班卡晚于工作时间 → **迟到**；下班卡早于工作时间 → **早退**；缺卡记录为**缺勤**（当前口径；规划中：缺卡先转待核实异常，结合班次/请假/补卡再定终态）。
- 打卡时间取服务器时间，精度到分钟。

### 2.2 请假
```
提交请假（状态=待审批）
   ├─ 审批人通过（状态=已通过）→ 扣减对应假期余额（原子防超扣）
   │        └─ 提前返岗：销假（状态=已销假）→ 返还剩余天数余额
   ├─ 审批人驳回（状态=已驳回）→ 无影响
   └─ 提交时同时发起 Flowable 流程；流程未部署则降级为本地直批
```
- 请假类型：事假 / 病假 / 年假 / 调休（字典 biz_leave_type）。
- 天数 ≥0.5，支持 0.5 步进；开始/结束日期必填，事由必填。
- **销假**仅限"已通过"的请假，销假后按未消耗天数返还余额（CAS 防重，重复销假只成功一次）。
- 重复审批/并发审批由状态条件更新（CAS）拦截，不会扣两次余额。

### 2.3 补卡
```
提交补卡（日期 + 类型[补上班卡/补下班卡] + 时间 + 原因）→ 待审批
   ├─ 通过 → 自动回写当天考勤（按补卡时间修正迟到/早退/缺勤）
   └─ 驳回 → 无影响；待审批状态可撤回（删除）
```
- 仅能补自己（creator 校验），撤回仅限"待审批"状态。

### 2.4 假期余额
- 按类型（事假/病假/年假/调休）分别记账；请假扣减、销假返还均为原子操作。
- 余额不足的请假允许提交（审批环节控制），余额展示于工作台与请假页。

## 三、协作审批（审批中心）

- **审批中心**聚合三类待办：请假 / 报销 / 补卡，页签带角标数量。
- 操作仅两种：**通过**（status→1）/ **驳回**（status→2，需填驳回原因）；重复审批被 CAS 拦截。
- 通过报销会自动生成记账凭证（见 FMS）；通过补卡会自动回写考勤。
- 有审批权限的账号（生产为管理员）会在待办产生时收到**站内信提醒**；审批完成后**申请人收到结果通知**（含驳回原因）。
- 权限：`biz:approval:query`（看待办）/ `biz:approval:audit`（审批操作）。

## 四、进销存

### 4.1 采购单
```
创建（状态=待确认，不动库存）
  → 确认（状态=已确认）
      → 完成（状态=已完成）
          ├─ 库存自动入库（quantity 增加）
          ├─ 成本移动加权：新成本 =（原库存×原成本 + 本次金额）/（原库存+本次数量）
          ├─ 生成记账凭证：借 库存商品 / 贷 应付账款
          └─ 生成 WMS 上架任务
  → 作废（待确认/已确认可作废，状态=已作废）
```
- 单号：采购编码留空则自动生成（前缀 CG，时间戳+随机，数据库唯一索引兜底）。
- 已完成单据与库存/凭证绑定，**禁止修改**；纠错走退货/冲销。

### 4.2 销售单
```
创建（待确认）→ 确认（已确认；此时按客户信用额度校验，超额拒绝）
   → 完成（已完成）
       ├─ 库存自动扣减（不足直接拒绝）
       └─ 生成 WMS 拣货任务
作废：待确认/已确认可作废
```
- **信用额度规则**：额度=动态公式「(已确认+已完成销售合计) − (收款合计−收款冲销)」，确认即占用、收款即释放、**冲销收款则恢复被该笔收款释放的占用**（占用回升）；超限拦截确认。
- 单号留空自动生成（前缀 XS）。

### 4.3 库存与流水
- `biz_stock` 为唯一库存事实；库存流水（stock_move）**只增不改、禁止删除**——纠错一律用"冲销"生成反向流水。
- 预警：库存低于下限触发站内信提醒（每日 Job）。

### 4.4 库存盘点 / 退货
- 盘点：录入实盘数 → 生成调整流水修正库存。
- 退货：关联原单退货，入库/出库方向相反，同样走流水。

### 4.5 在途库存
- 已确认未完成的采购单按产品+仓库汇总为"在途"，供缺货决策参考。

## 五、收付款

- 收款/付款可关联销售单、采购单、合同；**requestId 幂等**：同一编号重复提交返回原流水，编号相同但内容不同则拒绝。
- 冲销：`POST /biz/payment/reverse`，生成反向流水并释放信用额度占用（收款冲销会释放对应销售额度）。
- 审批通过的报销自动生成应付职工薪酬凭证（与 FMS 联动）。

## 六、CRM（客户/合同/线索/商机）

- **客户信用额度**：客户档案可设额度（0=不限额）；确认销售时实时校验。
- **合同**：维护起止日期，到期前 N 天进入到期提醒（站内信）。
- **线索 → 商机 → 合同**：转化链路；跟进记录（followup）记录每次联系。

## 七、FMS 财务

- **科目**：标准科目表（1001 库存现金 / 1002 银行存款 / 1122 应收 / 1405 库存商品 / 2202 应付 / 2211 应付职工薪酬 / 6001 收入 / 6401 成本 / 6602 管理费用…）。
- **凭证**：借贷必平（校验拦截）；状态=草稿 / 已记账；已记账不可删，手工凭证筛选口径为 `source_type IS NULL`。
- **自动凭证联动**：采购完成→借库存商品贷应付；报销通过→借管理费用贷应付职工薪酬。
- **报表**：利润表（收入/费用）、资产负债表（资产=负债+权益+净利润 恒等式校验）、科目余额（仅已记账凭证）。
- **移动加权成本**：见 4.1，出库结转自动按最新成本。

## 八、WMS 仓储

- **模型**：库位库存是主库存的"分配视图"——上架/下架只动库位表，不动 `biz_stock`。
- **上架**（未分配 → 库位）：校验未分配量足够；**下架**（库位 → 未分配）：校验库位量足够；**移库**：同仓库库位间移动。
- **作业任务**：采购完成自动生成上架任务，销售完成自动生成拣货任务；上架/下架动作按 FIFO 消耗进行中任务，支持部分作业（进度条）。
- 守卫式扣减：SQL 层 `quantity + delta >= 0`，并发安全。
- 未分配量 = 主库存 − Σ库位库存；销售完成后为负数表示"货已扣但待拣"（**现状口径**；规划中改为预占量/待拣任务/暂存区域的正向表达）。

## 九、通知与消息

| 事件 | 通知对象 | 渠道 |
|---|---|---|
| 请假/报销/补卡提交 | 审批人（管理员） | 站内信【审批待办】 |
| 审批通过/驳回 | 申请人 | 站内信【审批结果】（含驳回原因） |
| 合同/产品到期、库存低于预警 | 管理员 | 站内信【到期提醒】（每日 Job） |
| 每周一经营摘要 | 管理员 | 站内信（经营周报，定时 Job） |

- 站内信在移动端「消息」页与 PC 端右上角铃铛均可查看；支持全部已读。
- 模板存于 `system_notify_template`（params 必须为 JSON 数组格式）。

## 十、AI 知识库（RAG 问答）

- 上传 `.txt/.md`（≤2 MiB）→ 自动分块向量化（Qdrant，租户+知识库双重隔离）→ 文档状态 READY。
- 问答：自然语言提问，返回**带引用来源（文档名）**的回答；无依据时明确回复"知识库中没有找到依据"。
- 问答链路（当前）：嵌入检索 + 生成模型（SenseNova，OpenAI 兼容网关）；知识库问答入口在「AI 大模型 → AI 知识库」。竞赛项目（race 分支）另有 Python 侧混合检索实现（bge-m3 + BM25），属独立环境，两者不混用。

## 十一、移动工作台（/m/）

- 首页 = **消息**（同事聊天 + 站内通知双分段）；其他页签：工作台 / 审批 / 消息 / 我的。
- 工作台：圆形打卡按钮（状态机：未上班→上班打卡→下班打卡→已完成）、本月加班/今日考勤/待办审批三卡、8 项快捷入口。
- 审批中心：三页签待办 + 通过/驳回（驳回必填原因）；请假页含"销假"；报销/补卡支持撤回（仅待审批状态）。
- 登录账号与 PC 一致；单设备互踢见第一节。

## 十二、关键状态机速查

| 单据 | 状态码 | 流转 |
|---|---|---|
| 请假 | 0 待审批 → 1 已通过 / 2 已驳回；1 → 3 已销假 | 提交/审批/销假 |
| 报销、补卡 | 0 待审批 → 1 已通过 / 2 已驳回 | 提交/审批；0 可撤回 |
| 销售、采购 | 0 待确认 → 1 已确认 → 2 已完成；0/1 → 3 已作废 | transition + complete |
| AI 文档 | PROCESSING → READY / FAILED | 上传/解析 |

## 十三、通用业务规则（跨模块）

1. **单据完成才触发库存/凭证/任务联动**（当前实现；规划中按业务事件细分确认/收货/发货/记账时点）；创建不动库存。
2. **流水只增不改禁删**——纠错一律冲销。
3. **状态流转全部 CAS**（`WHERE status=旧值`），并发重复操作只成功一次。
4. **金额一律 BigDecimal**；信用额度确认即占用、收款即释放。
5. **数据可推导**：流水/凭证/任务由单据+业务事件推导，禁止直接改库；完整重建还需成本快照、核销关系等上下文（详见 race 评审 6.1）。
6. 移动端与 PC 同账号单设备互踢；会话失效统一跳登录页。
