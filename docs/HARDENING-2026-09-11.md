# 第二、三轮业务加固与升级说明

本次升级包含服务端、配套 `enterprise-pro-ui` 和数据库迁移，必须一起发布。
执行数据库升级前暂停业务写入并备份；不要把新应用连接到未完成迁移的数据库。

## 实现变化

- 收付款登记、手工冲销、退货红冲使用关联单据行锁；同一单据的金额检查和流水写入处于同一事务。累计金额使用当前读，避免 MySQL 可重复读的旧快照。
- 登记支持 `requestId`。相同编号与相同内容重试返回原流水，编号被不同内容复用则拒绝。前端每次新建生成一个编号，在请求失败重试时保留。
- `POST /biz/payment/reverse` 接收 `{id, reason}`，原因必填且不超过 200 字。冲销追加负数流水，保存 `reversalOfId`；重复冲销返回同一结果。`DELETE /biz/payment/delete` 明确拒绝删除。
- 退货红冲保存 `sourceReturnId`，按原账目关联合同分摊，保留合同维度。负数流水不再作为可手工冲销的入口；已发生退货导致余额不足时，拒绝全额冲销原收款。
- 收付、冲销、退货、盘点、商机生成合同统一采用随机文档编号，数据库唯一索引兜底。销售/采购手填单号同样受唯一约束保护。历史重复编号重新编号前保存在 `legacy_document_no`，主键和金额不变。
- 库存及采购、销售、退货、盘点、库存流水持久化 `productId/warehouseId`；假期配额和请假持久化 `employeeId`。名称保留为展示快照。
- 库存初始化按产品加数据库锁，支持多实例；增加租户内库存唯一约束。现存库存数量通过盘点调整，直接改数量或删除库存被拒绝。
- 员工资料增加 `userId` 关联登录账号。新账号应在员工资料中绑定；未绑定时工作台仍可打开，请假业务要求先建立明确的员工关联。不会按昵称自动猜测归属。
- BPM 请假回调重复投递不会重复扣余额；订单编辑和完成、请假编辑和审批使用同一行锁，避免使用编辑前的数量/天数。负数请假被拒绝，已审批请假和已使用配额保留记录。配额调低后扣减检查数据库当前上限，避免旧事务快照绕过。
- 历史生成器只输出到新的 `generated/<批次>` 目录，保护手写实现。

## 数据库版本

`sql/migrations/V001__schema.sql` 归并现有 154 张表的结构。`V001__seed.sql` 只包含菜单、字典及最小角色/租户配置，不包含用户密码和业务记录。

`tools/migrate.py` 管理版本 002，使用 `biz_schema_history` 记录校验和及执行时间，使用数据库锁防止两个迁移同时运行。MySQL DDL 隐式提交，因此升级操作按可重入步骤执行；发生失败后必须检查错误，恢复备份或修正原因后再运行。已应用版本的脚本不可再编辑，后续变更应增加版本。

默认只预检查，只有 `--apply` 才修改。工具不连接固定服务器，凭据从下列环境变量读取：

```
BIZ_DB_HOST
BIZ_DB_PORT
BIZ_DB_NAME
BIZ_DB_USER
BIZ_DB_PASSWORD
```

```powershell
python -m pip install -r tools/requirements-dev.txt
python tools/migrate.py --report migration-issues.json
python tools/migrate.py --apply --mapping migration-mapping.json
```

### 历史名称映射

预检查遇到同租户同名产品/员工、多个登录账号指向同一员工，或重复的库存、配额余额记录，会在改表之前停止。映射文件按报告中的 `key` 指定实际主数据 ID，例如：

```json
{
  "biz_stock:123:product": 456,
  "biz_leave:789:employee": 321
}
```

映射值必须是该租户、该名称的候选 ID。重复余额记录必须先核对合并，不能靠选 ID 跳过。只有缺少主资料的历史名称会生成带 `MIG` 编号的主资料；数量和金额不会由工具推算或修改。

本地预检查结果保存在工作区 `.enterprise-pro-work/migration-issues.json`，该清单未纳入 Git。正式库应重新运行预检查，不直接使用本地清单替代。

### 空库初始化

先创建 UTF-8 MySQL 空库，设置上述环境变量后运行 `python tools/migrate.py --apply`。随后设置自己的 `BIZ_BOOTSTRAP_ADMIN_PASSWORD`（至少 12 个字符），运行：

```powershell
python tools/bootstrap_admin.py
```

已有用户的库会拒绝初始化管理员。首次安装不带默认密码；第三方集成、BPM 流程模型和定时任务按实际使用情况另行配置。

## 配置与扫描告警

共享 YAML 中的 20 处字面量密码、密钥已改为环境变量。开发机原值保存在 Git 忽略的 `application-private.properties`，通过可选配置导入读取；其他环境参照 `application-private.example.properties` 提供所需值。不要把私有配置加入版本控制。

测试账号密码由 `BIZ_TEST_ADMIN_PASSWORD` / `BIZ_TEST_PEER_PASSWORD` 等环境变量提供。SSH 工具只接受已独立核验并登记到 `known_hosts` 的主机密钥，取消自动信任及命令行密码参数。

这不代表 Mimosa 门禁已经通过：已有报告还含扫描超时、覆盖范围不完整等运行问题，需要在原扫描环境重新执行，不能通过删除报告或跳过检查解决。

## 发布顺序

1. 备份数据库，完成目标库预检查及映射确认。
2. 暂停写入，在维护窗口执行迁移；确认版本 002 和有效记录 ID 回填完整。
3. 配置私有环境参数，部署后端和配套前端。原有删除收付款权限映射为冲销权限。
4. 验证选产品/仓库、采购入库、销售出库、登记收款、冲销及请假审批。若回滚应用，也需要恢复对应数据库备份，不只替换旧包。

本次未修改或迁移正式业务库，也未部署服务器。
